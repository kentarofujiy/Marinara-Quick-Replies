# Quick Reply

An extension for [Marinara Engine](https://github.com/SillyTavern/Marinara-Engine) that gives you a dropdown of
canned messages — click one to insert it into the compose box and (optionally) auto-send it. Ported from
SillyTavern's built-in Quick Reply extension, **text-snippet scope only** (see "Known limitations" — the
original is largely an STscript scripting IDE, and Marinara has no scripting engine to port that half onto).

## What it does

- **💬 dropdown button** in the compose row lists every active quick reply, grouped under its set's name.
  Clicking one inserts its message into the compose box and sends it (unless the set has "never auto-send" on).
- A quick reply can link to another **set** as a nested flyout submenu (pick "Greetings" → flyout shows that
  set's replies) — this is the dropdown's built-in context-menu system, not a separate right-click feature.
- **Three scopes**, merged into one dropdown: **Global** (always active), **Chat** (active only in this chat),
  **Character** (active only when chatting with this character, resolved from the chat's linked character(s)).
- **Auto-execute triggers**: a quick reply can fire itself automatically on startup, on chat change, after your
  message, or after an AI message — useful for a standing "remind me of the rules" or "check in" style reply. A
  reentrancy guard stops these from cascading into a runaway loop.
- **⚙ settings button** next to the dropdown: create/rename/duplicate/delete/import/export sets (as JSON files),
  link/unlink a set to Global/Chat/Character scope, and a full editor for each quick reply (icon, label, message,
  auto-execute flags, hidden flag, context-menu links).

## Installation

1. In Marinara Engine, go to **Settings → Addons → Extension Library**.
2. **Import** → select `quick-reply.json` from this folder.
3. Enable the extension.
4. Click ⚙ next to the compose box to create your first set and quick replies.

## Known limitations (scope decision — see NOTES-extension-api.md / NOTES-st-vs-marinara-frontend-diffs.md)

The original SillyTavern extension is roughly 65% an **STscript IDE**: a full code editor with syntax
highlighting, breakpoints, a step debugger, and ~25 `/qr-*` slash commands for chaining, piping, and parameterizing
quick replies. Marinara has no scripting engine to port that onto — its own slash-command system is a small fixed
set with no extension registration hook. This port keeps only the "button bar of canned messages" half:

- **No scripting.** A quick reply's message is inserted as literal text (optionally auto-sent), never parsed or
  executed as a script. `/`-prefixed messages are inserted as plain text too, not run as Marinara commands.
- **No `{{macro}}` substitution** inside quick reply messages — no app-internal macro engine is reachable from an
  extension, so `{{user}}`/`{{char}}`-style placeholders are not expanded.
- **No popout/draggable panel mode** — the dropdown is the only UI, no separate floating window.
- **No drag-and-drop reordering** — quick replies within a set reorder via ↑/↓ buttons.
- **Dropped triggers**: `automationId`/World-Info-Automation activation, `executeOnGroupMemberDraft`,
  `executeBeforeGeneration` — niche triggers tied to SillyTavern-specific systems.
- **Import doesn't preserve context-menu links** — exporting/importing one set at a time means a linked set's id
  from the source instance won't exist on import; re-link manually after importing.
- **Auto-send uses a synthetic Enter keypress** on the compose textarea (Marinara's send button has no stable
  selector to click directly) — verify this works in your build; see Development notes below if it doesn't.
- **Character scoping uses the chat's first linked character** (`chat.characterIds[0]`) — multi-character chats
  only get the first character's linked sets, not all of them.

## Development

Source lives in `extension.js`/`style.css`; the importable bundle (`quick-reply.json`) is generated by:

```sh
node build.mjs
```

`build.mjs` runs `selfcheck.mjs` first and refuses to write the bundle if any assertion fails. See
`../Marinara-Quote-Translator/NOTES-extension-api.md` (shared reference across all four ports) and
`../Marinara-Quote-Translator/NOTES-st-vs-marinara-frontend-diffs.md` for the Marinara slash-command/scoping
research behind this port's design decisions.

If auto-send (the synthetic Enter keydown in `dispatchAutoSend()`) doesn't reliably submit in your Marinara
build, the fix is locating Marinara's actual Send button element and calling `.click()` on it instead — this was
flagged as the one technically unverified piece during planning since it couldn't be tested outside a live
browser session.
